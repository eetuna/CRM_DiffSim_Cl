CP5.0 identified a domain shift problem:
  • Ensemble trained on synthetic golden data (smooth, ~2mm RMSE)
  • Validated on real NPZ data (complex, ~44mm RMSE)
  • Result: 100% MPC call rate (ensemble always uncertain)

CP5.1 addresses this by training directly on real NPZ windows:
  • Extract valid windows from real datasets (hold-aware filtering)
  • Collect MPC expert actions on these windows
  • Train ensemble via behavioral cloning (supervised learning)
  • Expected: Low uncertainty on real data → MPC call rate ≤30%

TECHNICAL DETAILS
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Training Approach: Windowed Behavioral Cloning
  1. Health gate extracts valid windows (CP4.7.8 hold-aware filtering)
  2. For each window:
     - Initialize state
     - Run MPC expert at each timestep (horizon=10, jacobian_mode="cpp")
     - Collect (p_tip, p_ref, u_expert) samples
  3. Train ensemble members via supervised learning:
     - Loss: MSE(u_pred, u_expert)
     - Optimizer: Adam (lr=1e-3)
     - Early stopping (patience=10)
     - Gradient clipping (max_norm=1.0)

Key Features:
  • Leverages CP4.7.8 hold-aware windowing (automatically skips NaN periods)
  • Reuses CP4.4c fast Jacobians (10× faster than Python)
  • No full-trajectory rollouts needed (avoids timeout issues)
  • Trains on actual real-world dynamics

Constraints Respected:
  ✓ No CP2/CP3 physics modifications
  ✓ Reuses existing infrastructure (CP4.7.8, CP4.7.9, GRUPolicy)
  ✓ Bounded budgets (smoke <60s, nightly <30min)
  ✓ No plan mode used
